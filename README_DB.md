# 🗄️ Traivl 데이터베이스 & Prisma 협업 가이드

팀원들과 협업할 때 데이터베이스 구조(Schema)가 변경되거나, 공통 데이터를 업데이트해야 할 때 사용하는 가이드입니다. 이 절차를 따르면 모든 팀원이 동일한 데이터를 가지고 개발을 진행할 수 있습니다.

---

## 1. 데이터베이스(DB) 데이터 업데이트 방법

데이터베이스에 새로운 목적지 정보를 추가하거나, 상세 설명 등을 수정하고 싶을 때 다음 순서를 권장합니다.

### 💡 권장 작업 순서 (데이터 수정자)
1. **`init.sql` 수정**: `database/init.sql` 파일을 원하는 정보(주소, 상세 설명 등)를 넣어 수정합니다.
2. **로컬 데이터 초기화 및 확인**: 아래 명령어를 통해 기존 데이터를 날리고 수정된 `init.sql`이 잘 들어가는지 확인합니다.
   ```bash
   # 기존 컨테이너 및 데이터 볼륨 삭제
   docker-compose down -v
   # 다시 실행 (init.sql이 자동으로 실행됨)
   docker-compose up -d
   ```
3. **확인 후 Git Push**: 데이터가 의도대로 들어갔다면 Git에 푸시합니다.
4. **팀원 공지**: 팀원들에게 DB 업데이트를 공지합니다.

### 🔄 팀원들이 최신 DB를 동기화하는 방법 (데이터를 받는 쪽)
다른 팀원이 `init.sql`을 업데이트하고 Git에 푸시했다면, 로컬 DB를 최신 상태로 맞추기 위해 다음 순서대로 실행하세요.

```bash
# 1. 변경된 최신 init.sql 받아오기
git pull

# 2. 기존 도커 데이터베이스와 볼륨(데이터) 완전히 삭제하기
docker-compose down -v

# 3. 최신 init.sql을 바탕으로 도커 다시 실행하여 DB 재생성
docker-compose up -d
```

---

## 2. Prisma 구조(Schema) 변경 시 대처 방법

`schema.prisma` 파일의 모델이 변경되었을 때(새로운 컬럼 추가 등), 팀원들이 `git pull`을 받은 후 수행해야 할 작업입니다.

### 🛠️ 팀원들이 수행해야 할 명령어
코드를 내려받으면 로컬 DB 구조는 예전 상태입니다. 아래 명령어로 최신 설계도를 반영하세요.

```bash
# 1. 변경된 설계도(Schema)를 바탕으로 Prisma Client 재생성
npx prisma generate

# 2. 로컬 DB 구조를 새로운 설계도에 맞게 업데이트 (데이터 동기화)
npx prisma db push
```

> **참고**: `npx prisma db push` 대신 `docker-compose down -v`를 통해 전체 초기화를 하면 `init.sql`에 담긴 최신 데이터까지 한꺼번에 동기화되므로 더욱 확실합니다.

## 💡 협업 꿀팁
*   **스키마 변경 시**: Git Push 하실 때, 팀원들에게 **"DB 스키마가 변경되었으니 npx prisma db push를 실행해 주세요"**라고 한마디만 남겨주세요.
*   **데이터 풍성하게 만들기**: 우리 프로젝트는 데이터가 핵심입니다! `init.sql`을 풍성하게 채워주시면 팀원 모두가 더 좋은 환경에서 개발할 수 있습니다.
